# Workstream: Calendar and weather

> Spec written for the iteration 6 builders. Status and where the code is: docs/HANDOFF.md. Shared rules: docs/workstreams/README.md. Contract: docs/EVOLUTION.md.

a recognizable Provo calendar and real weather.
1. Research official dates with WebSearch/WebFetch and cite URLs: BYU 2026–27 academic calendar (first day of classes, holidays, reading days, finals for Fall 2026, Winter 2027, Spring/Summer 2027), UVU 2026–27 academic calendar, BYU's 2026 home football schedule (opponents, dates, kickoff times if published), BYU devotionals and forums (Tuesdays 11:05 am in fall/winter; dates/speakers if published), General Conference (October 2026 and April 2027 — verify dates), BYU Homecoming, freshman move-in, Thanksgiving break, Christmas break, MLK Day, Presidents' Day, Memorial Day, Pioneer Day, July 4 Stadium of Fire / America's Freedom Festival, Halloween, Valentine's Day, finals weeks. Write ucsim/config/calendar/2026_27.yaml: id, label, date or range, time if known, place (name + lon/lat, e.g. LaVell Edwards Stadium, Marriott Center), kind, basis (real with source URL / rule / hypothetical), effects (no_class, finals, travel_home_likely, open occasion kind + audience). Write recurring rules (ucsim/config/calendar/rules.yaml) so later simulated years get plausible dates (basis: rule).
2. ucsim/engine/calendar_real.py loads both and answers items_on(day), term(school, day), in_finals(school, day), no_class(school, day), holiday(day); make core.Calendar delegate to it while keeping all its existing method names working for every caller, so terms, exam weeks (today approximated from term progress) and holidays become the real ones. Check world.yaml start_date (2026-08-24) against BYU's/UVU's real first day; keep the simulation start but make classes begin on the real date if it differs.
3. Weather: daily Provo observations (TMAX, TMIN, PRCP, SNOW, SNWD) from NOAA NCEI's public-domain daily summaries, station USC00427064 (PROVO BYU) or a nearby station if incomplete — try https://www.ncei.noaa.gov/access/services/data/v1?dataset=daily-summaries&stations=USC00427064&startDate=2015-08-01&endDate=2026-07-31&dataTypes=TMAX,TMIN,PRCP,SNOW,SNWD&units=standard&format=csv (Open-Meteo's archive API is a fallback, CC BY 4.0). Commit a compact CSV ucsim/config/sources/weather_provo_daily.csv with a sidecar .json (source, station, retrieval date, license). The simulation runs in 2026–27, past the data, so a world uses a chosen weather year (default: the most recent complete Aug–Jul year; selectable in world.yaml and as an environment variable a What-if can set, e.g. "replay the snowy winter of 2022–23"). Fill gaps from the climate normals already in world.yaml (labelled).
4. Environment (ucsim/engine/systems/environment.py): daily env flags tmax_f, tmin_f, precip_in, snow_in, snow_depth_in, weather_label ('snowstorm', 'rain', 'clear', 'hot'…), calendar_items, no_class, finals_BYU/finals_UVU; keep temp_f, outdoor_appeal, holiday, conference and exam_week_* working (now from real data). Modest, evidence-labelled weather effects: snow/rain lower outdoor appeal (existing pathway) and slow travel (travel.py reads env['snow_in']); cold/snowy evenings slightly lower occasion attendance — expose env['weather_penalty'] for the occasions system to read; mechanism parameters in a registry YAML.
5. Calendar occasions: for items people attend (home football games at LaVell Edwards Stadium, devotionals/forums at the Marriott Center, Homecoming events, conference-weekend watching at home or with friends, Stadium of Fire), plan open occasions into sim.book on their days (origin 'calendar', causes kind 'calendar'), with kinds in ucsim/config/occasions/30_calendar.yaml defining audience/base/interest/capacity (fields documented at the top of 00_core.yaml). Another builder is building the occasions system in parallel; it resolves attendance for every open occasion generically from those fields — you only plan them (make your planning a small hook, e.g. in environment.daily or a tiny 'calendar' system registered in sim.py). Conference weekends: no regular Sunday ward meetings — verify faith.py/activity.py honor env['conference'] and add the minimal hook if not. Leave travel_home_likely (Thanksgiving, Christmas) as data for the family builder (later wave).
6. API ucsim/api/routes_calendar.py: GET /api/calendar/items?from=&to= (basis, source, label), GET /api/calendar/weather?from=&to= (daily series and the weather year); keep the existing /api/calendar working. Workbench tool web/src/bench/tools/Calendar.tsx: a horizontal strip of weeks with term/finals/holiday bands, items as markers (real vs rule vs hypothetical styled differently), a weather row (temperature line, snow/rain marks); clicking a day sets the selection's time window; clicking an item focuses it (Ref kind 'calendar').
Tests: tests/test_calendar.py (dates resolve; terms/finals/no-class; weather by weather year; occasions planned on game days with the right kind; determinism).
