# Workstream: Scales: making every number readable

> Spec written for the iteration 6 builders. Status and where the code is: docs/HANDOFF.md. Shared rules: docs/workstreams/README.md. Contract: docs/EVOLUTION.md.

make every number readable. The owner said: "the number values for variables still don't make sense; for loneliness, I don't know what the highest or lowest possible values are, or what either mean. If there's a simple way to include the scale for each that I can look at, that would be helpful in making sense of the data." Today ucsim/scales.py gives each numeric field its two ends in words and a note (served in VarSpec.to_dict()['scale']), shown mostly as tooltips.
1. Backend (ucsim/scales.py): for every numeric person field: min, max, units in words; anchors: 3–5 points along the range with words (e.g. loneliness 0 "not lonely — has people and feels connected", 0.25 "lonely now and then", 0.5 "often lonely", 0.75 "lonely most days", 1 "extremely lonely — isolated nearly all the time"); how: one sentence on how the model measures it (from the variable's desc/init/source: survey item wording where survey-based, "a feeling the model composes from…" for composed states, standard scores for traits…); keep percent/z/levels handling. Write anchor words carefully for every composed feeling, inner-life field, faith field, relationship and other high-traffic fields (see config/variables/*.yaml); sensible generic anchors for the rest. Also the relationship (edge) fields shown in the UI (closeness, liking, trust, attraction, believed interest, disclosure, support, hurt), in a separate mapping.
2. ucsim/api/routes_scales.py: GET /api/scales?u=&vars=a,b → per field the scale plus the live distribution among people present (p10, p25, median, p75, p90, mean, n, a 20-bin histogram), optionally for a cohort (filter= JSON in the query DSL, evaluated with analysis/query.evaluate_filter as other endpoints do); GET /api/scales/value?u=&var=&value= → the value's percentile among people present.
3. web/src/kit/Ruler.tsx: a compact, beautiful SVG ruler: the track from min to max with anchor ticks and words (abbreviate gracefully when narrow; full words on hover), the population's middle half as a band and 10th–90th as whiskers with a median tick, and the value marker with a caption such as "0.62 · lonely most days · higher than 78% of people". Variants: inline (one line, for tables and person pages) and full (all anchor words). A ScaleCard popover shows the full ruler, the description, how it's measured and the evidence label; open it by clicking any value rendered with a small <Val var=.. value=..> wrapper you add in web/src/kit/.
4. Use it where values appear: the person page's feelings and inner-life values (web/src/views/PersonView.tsx, InnerLife.tsx), Explore's field pane (views/explore/FieldPane.tsx, FieldCanvas.tsx where a distribution is shown), and other places a raw 0–1 number appears without context (grep). Don't edit App.tsx, store.ts or nav.ts (another builder is changing navigation).
5. A Scales glossary workbench tool web/src/bench/tools/Scales.tsx (exports tool): every field grouped by domain with its inline ruler and anchors, searchable; clicking a field focuses Ref {kind:'var'}.
Tests: tests/test_scales.py (every numeric person field has ordered anchors inside its range; the endpoint returns sensible quantiles on a small world). npm run build must pass; screenshot the ruler and the glossary with Playwright on a small running world (python -m ucsim.api.server --scale 0.05 --warmup 7 --port 8124 after building the web app) and look at them; save docs/img/scales-*.png.
