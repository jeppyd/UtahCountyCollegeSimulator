# Workstream: Ask the world and interviews

> Spec written for the iteration 6 builders. Status and where the code is: docs/HANDOFF.md. Shared rules: docs/workstreams/README.md. Contract: docs/EVOLUTION.md.

"Ask the world" and "Interviews", grounded and checked. Read docs/EVOLUTION.md §10, docs/LLM_ROADMAP.md (T1, T2, F3 and the guardrails), docs/WHATIF_LLM.md, and the existing LLM layer: ucsim/llm/backends.py (Claude Code CLI on the owner's subscription, Codex CLI, OpenAI-compatible local servers such as LM Studio), compiler.py (background jobs, settings in ~/.ucsim/llm.json, tool loop), mcp_server.py, entities.py; and analysis/inner.py, explain.py, query.py, person.py. The owner has a GPU for a local model and a Claude Pro login; default to the local model for interviews when one is configured (fast, private) and Claude for Ask the world; let the owner choose per feature.
1. ucsim/llm/talk/facts.py: deterministic fact builders producing typed claims {id, kind: fact|perception|cause|measurement|belief, subject (a Ref like {kind:'person', id}), text (a plain sentence a person could read), value?, band? (the word band for a level), refs: [Ref], weight?}. Person dossier for interviews from inner_life (perceived side only: their beliefs about friends, support and others' interest; their memories via a non-rehearsing read; intentions; coping; drives; relationships as they perceive them), recent events with their own decisions and top factors (sim.decisions — may be empty; handle it). World facts via a fixed set of query tools: find people by filter (query DSL) with counts; rank places (complexes, wards) by a field; event counts by type/place/window; most affected by a What-if (analysis/explain.most_affected); why a number changed for a cohort (cohort_term_attribution and event effects); a person's feeling decomposition (explain_state); event chains — and the trace engine ucsim.analysis.trace if importable (another builder is writing it; skip gracefully if absent).
2. ucsim/llm/talk/check.py — the checker. An answer is JSON {sentences:[{text, claims:[ids]}]}. Rules: every sentence cites ≥ 1 claim; every number in the text (including spelled-out numbers and percentages) matches a value in a cited claim within rounding; every person/place name matches a cited claim's subject/refs; causal connectives (because, so, led to, caused, made, due to, causal 'since', which is why…) require a cited 'cause' claim (or a measurement claim marked as a decomposition share above a threshold); feeling and level words (lonely, very stressed, happy, close…) must match the band of a cited claim on that field (a lexicon of words → field + band); in interviews only perception/belief/self-fact claims may be cited, never another person's hidden state. A verdict per sentence with reasons; one repair round with the reasons; then drop failing sentences and show them as "removed: reason". Build tests/data/talk_cases.json with ≥ 60 seeded statements (true and subtly false: wrong number, wrong person, unsupported 'because', wrong intensity, hidden-state leak) and report the checker's catch rate and false-alarm rate, with a test enforcing a floor.
3. ucsim/llm/talk/ask.py and interview.py: background jobs like compiler.py (start / poll / cancel) on backends.py; prompts in ucsim/llm/prompts/talk_*.md. Ask: the model picks tools (JSON), the server runs them and builds facts, the model composes an answer citing claims, check, repair, return {sentences (ok flags, claim ids), claims, refs, removed, tools_used, backend, seconds}. Interview: observational only (never changes the world, never rehearses memories), first person, from the dossier; sensitive fields excluded by default — porn_use, n_sex_partners, premarital_sex_current, ever_cheated, SEXUAL/NCMO tie flags and any variable whose YAML flags include 'sensitive' (the survey builder is adding that flag); safe-messaging for depression (no methods, no clinical advice); no generated theology; an option to interview the same person in the What-if world.
4. ucsim/api/routes_talk.py: GET /api/talk/status (backends available and the per-feature choice), POST /api/talk/settings, POST /api/talk/ask → job, GET /api/talk/ask/{job}, POST /api/talk/ask/{job}/cancel, POST /api/talk/interview/{i} (question + history) → job, polled the same way. Use the same local-only guard the What-if endpoints use (server.py _local_only).
5. Workbench tools web/src/bench/tools/Ask.tsx and Interview.tsx (export tool) and web/src/kit/Answer.tsx: sentences with every cited person/place/event as a clickable chip (focus via useBench), a "what this rests on" expander listing the claims, removed sentences with reasons, backend and time taken. Interview: the focused person; a short conversation; a toggle "show where their view differs from what's true" (from inner_life's perceived-vs-actual, computed deterministically, not by the model).
6. Tests without real model calls: a fake backend returning scripted JSON through the whole pipeline; checker unit tests; the evaluation floor. If a local OpenAI-compatible server or the claude CLI happens to be available you may smoke-test manually, but don't depend on it.
