# Workstream: The workbench (new simpler interface)

> Spec written for the iteration 6 builders. Status and where the code is: docs/HANDOFF.md. Shared rules: docs/workstreams/README.md. Contract: docs/EVOLUTION.md.

the new, simpler interface: the Workbench. The owner said: "the application is too complex for me. I want it simplified; don't make it like some SaaS app that sets predetermined dashboard-type elements — I don't like those. I want the raw tools laid out for me that I can set up myself, in a way that's easy to assemble. Simulations are happening, but I'm having trouble SEEING the connections. I want to see the story — not in a way that the game auto-generates neat things for me, but a way for me to select and see causal events, the chain reaction of things, both at micro and macro level." Read docs/EVOLUTION.md §12, web/src/bench/registry.ts and selection.ts (the contract: tools register from web/src/bench/tools/*.tsx; one shared selection), and the existing app (web/src/App.tsx, store.ts, api.ts, hud.tsx, game.tsx, components.tsx, views/*) to reuse its API client, styles and components.
1. The bench (web/src/bench/Bench.tsx + bench.css): opens empty except for a shelf of tools (grouped, each with its one-sentence hint) and one line of guidance. Add a tool (click or drag from the shelf), move, resize (12-column grid; simple pointer-based drag/resize — no new dependency unless clearly worth it), duplicate, close. Each panel has a thin header: tool name, what it's showing ('following the selection' or 'pinned: Maya Johnson'), a pin toggle (freeze to the current selection), the tool's own options, close. Layout and panel options persist per world in localStorage (keyed with worldKey(status) from store.ts). No pre-built dashboards.
2. A selection bar at the top of the bench: chips for the selected people (or a filter — reuse store.ts Cond and existing filter pieces where helpful), the time window and the focused item; back (history); clear. A shared web/src/kit/RefChip.tsx renders any Ref (person name via existing name helpers, event label, place name…) and on click offers Select / Add to selection / Trace / Open in its natural tool. Every tool uses RefChip for entities so everything is clickable everywhere.
3. Core tools (web/src/bench/tools/), simple, honest and fast, using existing endpoints (add client functions to api.ts as needed):
 - Map: people as dots at their current place or at home, colored by any field (reuse helpers in components.tsx/analysis.ts), selected people highlighted, click a dot to focus, drag a box to select; an honest note of the moment shown (the model simulates a few moments a day, not continuous movement); do not edit views/MapView.tsx — build a compact map with deck.gl/MapLibre as MapView does.
 - People: a table of the selection (or everyone, filterable) with a column picker over any field; click a row to focus.
 - Life: one person's life on lanes over time — events by category, relationships starting/ending, moves, school and work, and a few chosen feelings as sparklines (/api/person/{i}/history); click an event to focus it.
 - Timeline: events over time for the selected people (a row per person up to ~30, a density strip by category beyond); brush to set the time window; click to focus.
 - Measure: any field over time for the selection vs everyone (/api/cohort_timeline, /api/fields/timeline) and its distribution now, with the field's scale words (VarSpec.scale). Another builder is making web/src/kit/Ruler.tsx; if it isn't in your worktree, show the scale note and leave an obvious slot for the ruler.
 - Ties: the selected people's relationships (/api/person/{i}/network), colored by kind; click a person to focus.
 - Place: a complex / ward / venue summary (existing places and institution endpoints): who lives or goes there, culture over time, events there.
 - Compare: Original vs What-if for the selection when a What-if exists (existing compare endpoints).
 - Events: a searchable list filtered by the selection.
 Other builders are adding Trace, Chains, Scales, Ask, Interview and Calendar tools as files in the same folder (they'll appear on the shelf automatically) — don't create files with those names.
4. Navigation: the app opens on the Workbench. Top-level navigation becomes Workbench · What-if · How it works, plus a "Classic views ▾" menu holding every existing page (World, Map, People, Relationships, Places, Events, Explore and the research desk) so nothing is lost. Keep the HUD (clock, speeds, lens). Add a short plain-language "The workbench" section to the in-app guide (web/src/views/Guide.tsx).
5. Quality bar: calm and beautiful — more instrument than dashboard (thin rules, generous space, clear type, the existing palette; light and dark). Panels handle empty states ("Select someone on the map or in People"), loading and errors gracefully, and re-render efficiently while time runs (respect store dataVersion and the useAsync pattern in game.tsx). npm run build must pass. Check it visually: build the web app, run the server with a small world (python -m ucsim.api.server --scale 0.05 --warmup 14 --port 8123) and drive it with Playwright to screenshot an empty bench and a bench with Map + Life + Timeline + Measure on a selected person; look at the screenshots, fix what looks wrong; save final screenshots as docs/img/bench-*.png.
